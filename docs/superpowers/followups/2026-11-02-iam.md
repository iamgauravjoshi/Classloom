## Security and correctness hardening

- **Invitations after the inviter is demoted.** Open invitations aren't re-checked against the inviter's current rights when someone accepts. Consider revoking a demoted inviter's open invitations.
- **Invitation limits.** Resends don't count toward the 50-per-day school limit, and a rolled-back create still uses up one of those 50.
- **Revoking invitations.** Revoke has no escalation check, so anyone with `iam.manage` can revoke an Owner invitation.
- **Error handling.** The P2002 unique-violation matching uses a `JSON.stringify(meta)` substring. It needs a `meta.target` fallback and a unit test with adapter-shaped `meta`. The `role-changed` primary-key branch is untested.
- **Role edits.** There's no row lock before a role edit, so under concurrency the audit's `before` can be stale. Stray stored keys that aren't in the catalogue survive a reset.
- **Owners elsewhere.** `user_is_owner_elsewhere` ignores the other school's status.
- **CLI.** `schools:list` shows owners regardless of their membership status, and there's no CLI command to restore an owner.
- **Access denied.** The page renders with HTTP 200. It could return a real 403.
- **Retries.** `retryQuery` retries a 403 once.

## From the final fix check

- **Accepting an invite doesn't lock owner rows.** The owner check at accept doesn't lock owner membership rows, so a demotion that lands at that exact moment isn't serialised.
- **A refused accept shows a generic error.** When accepting is refused with 403 (a deactivated owner's seat, or an inviter who is no longer an owner), the join page shows a generic message. A specific "ask an owner to re-invite" would be clearer.
- **Token redaction misses encoded keys.** It matches only the literal `token=` key; a percent-encoded key would be echoed back unredacted.
- **Duplicate helper.** `roles.service.ts` keeps its own `permissionsOf`, duplicating the one in `permissions.ts`.
- **Throttled requests aren't marked no-store.** A 429 from the throttler doesn't carry `Cache-Control: no-store`.
