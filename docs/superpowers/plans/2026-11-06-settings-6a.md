# Number series and audit log (Phase 1, Part 6a) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Schools get four configurable number series, issued safely by a service Phase 2 will call, and holders of a new `audit.view` permission can browse, filter, expand and export the audit trail.

**Architecture:**

- **Pure rules in `@classloom/contracts`:** number patterns, the audit areas and the catalogue change.
- **New API `settings` module:** number series plus the allocation service.
- **New API `audit` module:** reads `audit_events` under RLS, with read-time target labels and a CSV export.
- **Two web Settings pages:** number series and the audit log.

**Tech Stack:** NestJS 11, Prisma 7, PostgreSQL 17 (RLS, upsert counters), Next.js 16, next-intl, TanStack Query, Orval, Vitest, Testcontainers, Playwright + axe.

**Spec:** `docs/superpowers/specs/2026-11-06-settings-6a-design.md` (section numbers refer to it).

## Global Constraints

- **Branch and commits:**
  - Branch `feat/p1-settings-6a` from `main` after PR #15 merges, or from `docs/settings-6a-spec` if it is still open.
  - Use Conventional Commits with the harness's Co-Authored-By trailer.
  - Open one PR against `main`.
- **Series:**

  | Key           | Pattern            | Reset           |
  | ------------- | ------------------ | --------------- |
  | `ENQUIRY`     | `ENQ/{AY}/{SEQ:4}` | `ACADEMIC_YEAR` |
  | `APPLICATION` | `APP/{AY}/{SEQ:4}` | `ACADEMIC_YEAR` |
  | `ADMISSION`   | `{SEQ:5}`          | `NEVER`         |
  | `FEE_RECEIPT` | `REC/{AY}/{SEQ:5}` | `ACADEMIC_YEAR` |

- **Pattern tokens:**
  - `{AY}` gives `2026-27`, with an ASCII hyphen;
  - `{YYYY}` gives `2026`;
  - `{YY}` gives `26`;
  - `{SEQ:n}` takes n = 1–8; zero-padded; longer values print in full.
- **Pattern rules:**
  - literal characters are `[A-Za-z0-9/_ -]`;
  - 1–40 characters;
  - `{SEQ:n}` exactly once;
  - the problems are `empty | too-long | bad-character | unknown-token | seq-missing | seq-repeated | seq-width`.
- **Counters:**
  - the period is the academic year id for `ACADEMIC_YEAR`, or `'ALL'` for `NEVER`;
  - `last_value` is a bigint ≥ 0, and the next number is `last_value + 1`;
  - the maximum sequence is 99,999,999, above which `NumberSeriesExhausted` is thrown.
- **Next number:** it must be greater than `last_value`. Otherwise 422 `next-number-too-low` with `{ minimum }`.
- **Switching the reset rule:** numbers never repeat. When the new pattern has no year token, the new period's counter starts at the highest number already issued (spec §3).
- **Audit areas:**
  - `people`: `role.`, `member.`;
  - `school`: `school.`;
  - `calendar`: `academic_year.`, `campus.`;
  - `academics`: `section.`, `sections.`, `stream.`, `subject.`, `subjects.`, `class_subjects.`, `house.`, `room.`;
  - `settings`: `number_series.`, `audit.`.
- **Audit API:**
  - `limit` defaults to 50, maximum 100;
  - newest first by `(created_at, id)`, with an opaque cursor;
  - `from` and `to` are inclusive dates in IST;
  - CSV allows up to 5,000 rows, else 422 `export-too-large` with `{ limit }`;
  - every export writes `audit.exported` with the filter in `after`.
- **Permissions:**
  - number series: `settings.view` to read, `settings.manage` to change;
  - audit: `audit.view` for the API and the page;
  - the catalogue gains `{ module: 'audit', actions: ['view'] }`;
  - Admin gets it (all permissions), Principal's defaults exclude it, and Owner keeps "all".
- **Audit actions and targets:**
  - the new actions are `number_series.updated` (target type `number_series`, target id = tenant id) and `audit.exported` (target type `audit`, target id = tenant id);
  - a change that alters nothing writes nothing.
- **Problem types:** `number-pattern-invalid` (`{ problem }`), `next-number-too-low` (`{ minimum }`), `export-too-large` (`{ limit }`).
- **Pages:** `/[locale]/settings/number-series` and `/[locale]/settings/audit-log`. Both nav items sit in the Settings group: "Number series" needs `settings.view` and "Audit log" needs `audit.view`.
- **Web quality bar:**
  - All copy lives in `messages/en.json`. Dates are shown as DD/MM/YYYY in IST.
  - Axe passes WCAG 2.1 AA in light and dark on the 6 device projects, with no overflow at 375 px. Touch targets are 44 px.
- **Environment:**
  - Use `npx -y pnpm@12.6.0 …`.
  - E2E runs with `E2E_API_PORT=4100 E2E_WEB_PORT=3200` and a web build made with `API_INTERNAL_URL=http://localhost:4100`.
  - Never skip hooks.
  - Write files only inside the repo or the scratchpad.

## Review Focus

1. **A school continuing from a paper register.** Setting the Admission next number to 4813 makes the next `next()` return `04813`. Setting it to 4812 or lower afterwards is refused (Task 3 test).
2. **Two admissions saved at the same moment.** They get consecutive, distinct numbers, and a save that rolls back doesn't burn a number (Task 3 concurrency test).
3. **A school whose year changes mid-cycle.** After "Make current" on the next year, `ACADEMIC_YEAR` series restart at 1 for the new year, while `ADMISSION` (`NEVER`) continues (Task 3 test).
4. **An audit event whose target was deleted** (a removed role or section) renders "a deleted role" and doesn't break the page (Task 4 test, Task 6 a11y).
5. **A long audit history on a phone.** Load more appends without losing filters, the filters survive a reload through the URL, and there's no horizontal scroll at 375 px (Task 6 a11y, Task 7 E2E).

### Task 1: Contracts

**Files:** create `packages/contracts/src/number-series.ts` and `audit.ts` with their tests. Modify `iam.ts` (and its test) and `index.ts`.

**Interfaces (Produces):**

- **Number series:**
  - `NUMBER_SERIES_KEYS = ['ENQUIRY','APPLICATION','ADMISSION','FEE_RECEIPT'] as const`, `NUMBER_SERIES_RESETS = ['ACADEMIC_YEAR','NEVER'] as const`.
  - `DEFAULT_SERIES: Record<NumberSeriesKey, { pattern: string; reset: NumberSeriesReset }>`.
  - `parseNumberPattern(pattern): { ok: true; parts: PatternPart[] } | { ok: false; problem: PatternProblem }`.
  - `formatNumber(parts, { yearStart: number; sequence: number }): string`.
  - `hasYearToken(parts): boolean`.
  - `numberSeriesSchema` is `{ key, name, pattern, reset, nextNumber: number, preview: string | null }`, plus `numberSeriesListSchema` and `updateNumberSeriesRequestSchema` (`{ pattern?, reset?, nextNumber? }`, at least one field, `nextNumber` an int 1–99,999,999).
- **Audit:**
  - `AUDIT_AREAS: Record<AuditArea, readonly string[]>` (the prefixes from Global Constraints).
  - `areaOfAction(action): AuditArea | null`.
  - `auditEventsQuerySchema` (`from?`, `to?` as YYYY-MM-DD; `actorUserId?`; `area?`; `cursor?`; `limit` 1–100, default 50).
  - `auditEventSchema` is `{ id, action, area, createdAt, actor: { userId, name } | null, target: { type, id, label: string | null }, changes: { field, before, after }[], ip: string | null, device: string | null }`.
  - `auditEventsPageSchema` is `{ events, nextCursor: string | null }`.
- **IAM:** `IAM_MODULES` gains `'audit'`, `PERMISSION_CATALOGUE` gains `{ module: 'audit', actions: ['view'] }`, and `BUILT_IN_ROLE_DEFAULTS.PRINCIPAL` excludes `audit.view`.

**Steps:**

- [ ] **Step 1: Failing tests.**
  - **Parsing:**
    - `parseNumberPattern('ADM/{YY}/{SEQ:4}')` is ok.
    - Each problem case is refused: `''`, 41 characters, `'A#{SEQ:3}'` (bad-character), `'{FOO}{SEQ:2}'` (unknown-token), `'ADM'` (seq-missing), `'{SEQ:2}{SEQ:2}'` (seq-repeated), `'{SEQ:0}'` and `'{SEQ:9}'` (seq-width).
  - **Formatting:**
    - `formatNumber(parse('ADM/{YY}/{SEQ:4}'), { yearStart: 2026, sequence: 12 })` is `'ADM/26/0012'`.
    - `{AY}` with 2026 gives `'2026-27'`, and with 2099 gives `'2099-00'`.
    - `{SEQ:3}` with 12345 gives `'12345'`.
  - **Defaults:** every `DEFAULT_SERIES` pattern parses.
  - **Audit areas:**
    - `areaOfAction('class_subjects.updated')` is `'academics'`;
    - `'number_series.updated'` is `'settings'`;
    - an unknown action gives `null`.
  - **Catalogue:**
    - `ALL_PERMISSIONS` includes `audit.view`;
    - the Principal default excludes `audit.view`, `iam.manage` and `settings.manage`;
    - the Admin default includes `audit.view`.
- [ ] **Step 2:** Run `npx -y pnpm@12.6.0 --filter @classloom/contracts test`. Expect FAIL.
- [ ] **Step 3:** Implement. Rebuild the contracts dist. Run the root typecheck; the web role editor may need the `audit` module label in `en.json` (`iam.permissions.modules.audit`), so add it.
- [ ] **Step 4:** Run the tests. Expect PASS.
- [ ] **Step 5:** Commit `feat(contracts): add number series patterns, audit areas and the audit permission`.

### Task 3: Number series API and allocation service

**Files:** create `apps/api/src/modules/settings/{settings.module,settings-problems,number-series.service,number-series.controller}.ts`, and register the module. Test: `apps/api/test/settings/number-series.int.test.ts`.

**Interfaces:**

- **Produces, for Phase 2:**
  - `NumberSeriesService.next(tx, key: NumberSeriesKey, year: { id: string; startsOn: string }): Promise<{ value: string; sequence: number }>`.
  - It is exported from `SettingsModule`.
- **Routes:**
  - `GET /settings/number-series` [`listNumberSeries`]
  - `PATCH /settings/number-series/:key` [`updateNumberSeries`]
- **Preview and next number:** both use the CURRENT academic year. `nextNumber` is `last_value + 1` for the current period, and `preview` is null when there's no current year.

**Steps:**

- [ ] **Step 1: Failing tests.**
  - **Reading:** GET returns the four defaults. With a current 2026-27 year, the Admission preview is `00001` and the Enquiry preview is `ENQ/2026-27/0001`.
  - **Concurrency:** 20 concurrent `next(tx,'ENQUIRY',year)` calls, each in its own `withTenant` transaction, return sequences 1–20 exactly once each.
  - **Rollback:** a `next()` inside a transaction that then throws leaves `last_value` unchanged, and the next call returns the same number (Review Focus 2).
  - **Year changes:**
    - After "Make current" on 2027-28, `next('ENQUIRY')` returns `ENQ/2027-28/0001`.
    - `next('ADMISSION')` keeps counting from the previous value (Review Focus 3).
  - **Next number:**
    - PATCH ADMISSION `{ nextNumber: 4813 }`, then `next()` gives `04813`.
    - PATCH `{ nextNumber: 4813 }` again gives 422 `next-number-too-low` with `minimum: 4814` (Review Focus 1).
  - **Pattern:** an invalid pattern gives 422 `number-pattern-invalid` with `problem`.
  - **Reset switches:**
    - Switching ADMISSION to `ACADEMIC_YEAR` with a pattern without a year token, after issuing 5, starts the year's counter at 5 (the next is 6).
    - Switching back to `NEVER` continues from the highest.
  - **Audit:** one `number_series.updated` row per change, with the key and the changed fields; a PATCH that changes nothing writes no row.
  - **Permissions:** a custom role with `settings.view` but not `settings.manage` gets 403 on PATCH. A role without `settings.view` gets 403 on GET.
  - **Isolation:** school B's counters are untouched by A's calls.
- [ ] **Step 2:** Run. Expect FAIL.
- [ ] **Step 3:** Implement.
  - `next()` uses a raw `INSERT … ON CONFLICT … DO UPDATE … RETURNING last_value` through `tx.$queryRaw`.
  - PATCH locks the series row with `FOR UPDATE` before changing `reset` or `nextNumber`.
  - Wrap the response DTOs in `withNullableProperties`.
- [ ] **Step 4:** Run. Expect PASS.
- [ ] **Step 5:** Commit `feat(api): configure number series and issue numbers safely`.
